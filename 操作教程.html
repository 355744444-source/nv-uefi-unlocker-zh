nv-uefi-unlocker 操作教程

你手上有一个 nv-uefi-unlocker-pack-v2.1.9.zip。这份教程从解压它开始， 一步一步走到「系统里读回覆盖值有效」。每一步都告诉你做什么、正常该看到什么、不对怎么办， 命令可直接复制，路径与包内真实结构一一对应。

包版本 v2.1.9 8 步 · 线性执行 GTX 16 / RTX 20 / 30 / 40 不可逆操作：无（易失） 需要重启 2–4 次

导这份教程怎么用

包里有两份文档，分工不同：本教程负责「照着做」，使用手册.html 负责「查细节」。 第一次操作只需要看这一份；遇到教程没解释的现象，再去手册对应章节。

动手之前先认一件事

这个工具不刷 VBIOS、不改驱动、不写注册表。它在系统驱动加载之前，从 U 盘接管一次 GPU 事务， 写入算力覆盖值，然后把控制权交回系统引导器。所以：断电就复原，没有「刷坏了」这种状态； 但反过来，每次冷启动都要重放一次，别指望一次搞定永久生效。

步 1解压这个包

DO做什么
  1. 把 nv-uefi-unlocker-pack-v2.1.9.zip 解压到一个纯英文、无空格的目录，例如 D:\nvunlock\。
  2. 不要双击进入压缩包直接运行里面的 .ps1 或 .exe——那样跑的是临时目录， 脚本取相对路径会失败，Windows 还可能给文件套上「来自网络」的拦截标记。
  3. 解压后进入 nv-uefi-unlocker-pack-v2.1.9\，**不要**再往下一层嵌套。
SEE看到什么

解压后的根目录应当有这 9 个条目，缺任何一个说明解压不完整，重新解压：

条目类型用途（你这次会不会用到）
README.txt文件包结构说明，纯文本，记事本可看
操作教程.html文件本文件，跟着做就行
使用手册.html文件查原理、故障、兼容性细节
快速上手.md文件一页纸速查，和附录 B 内容重叠
01_release-v2.1.9/目录会用到。制盘、诊断都在这里跑
00_checksums/目录事后审计用，正常操作不需要
02_diag/目录仅 Linux 诊断时用
03_docs-zh/目录上游中文原文档，需要原子级细节时查
04_source/目录完整源码 + git 历史，要自己编译才用
IF NOT不对怎么办
  • 解压报「路径太长」：换更短的解压目标，例如 D:\nvu\。04_source/ 里有较深的目录层级。
  • 看不到 04_source\.git：正常，资源管理器默认隐藏以点开头的目录和文件。不影响操作。
  • 杀软报毒 / 拦截 ssdiag-x86_64-windows.exe：这个 exe 内嵌一个交叉签名的内核驱动， 启发式容易误报。先核对 00_checksums\校验记录.txt 里的 SHA256，一致就放行；不一致就重新下载整包。

步 2确认这块卡能用

这一步花 2 分钟，能挡掉后面 80% 的无效操作。device ID 不在支持范围内，后面所有步骤都不用做。

DO做什么

在目标机上开一个 PowerShell（普通权限即可），先查型号与 device ID：

PowerShell · 任意位置
PS> nvidia-smi --query-gpu=name,pci.device_id --format=csv

# 多卡机器再查一下各卡的 BDF，后面选卡要用
PS> nvidia-smi --query-gpu=index,name,pci.bus_id --format=csv

然后进 01_release-v2.1.9\，跑一次只读的门状态检查（不加载任何驱动，最安全的第一步）：

PowerShell · 01_release-v2.1.9 目录内
PS> cd .\01_release-v2.1.9
PS> .\ssdiag-x86_64-windows.exe --dry-run
SEE看到什么

对着 device ID 查表，四段之内才继续：

device ID家族结论
0x1E02 – 0x1FFF
0x2182 – 0x21D1		Turing
GTX 16 / RTX 20		支持，但要先做第 4 步（开 GSP）
0x2200 – 0x22FF
0x2400 – 0x25FF		Ampere
RTX 30		直接可用，跳到第 3 步
0x2600 – 0x28FFAda
RTX 40		直接可用，跳到第 3 步
其他所有值RTX 50 / Pascal / GA100 等不支持，到此为止

--dry-run 正常时会打印平台门状态与它发现的每块 NVIDIA 显示设备。 看到卡被列出来、没有报「找不到设备」，就说明这一步过了。

IF NOT不对怎么办
  • nvidia-smi 不是内部或外部命令：没装 NVIDIA 驱动，或者装的是纯核显机器。先装驱动。
  • 只列出一个 AMD / Intel 显示设备：这台机器没有 NVIDIA 独显，工具不适用。
  • --dry-run 报错退出：确认是在 01_release-v2.1.9\ 目录里执行的（相对路径问题）； 仍报错就把完整报错留存，翻手册 07 章。
  • device ID 查不到：用 nvidia-smi --query-gpu=pci.device_id --format=csv,noheader 单独取一次， 去掉方括号和 10DE: 前缀再比对。
这一步过了但设备号很偏门怎么办

有些魔改卡（例如 3080 20GB）用的是非标准 device ID，可能落在段内也可能落在段外。 段内就正常走；段外不要硬试，先去 03_docs-zh/compatibility.md 查有没有同型号证据。

步 3关掉 Secure Boot 与快速启动

两个都要关，但关的不是一件事：Secure Boot 挡住的是「谁能在我开机时运行代码」， 快速启动挡住的是「我这次重启是不是真的重启」。后者最坑——它会让「关机再开」实际走休眠恢复。

DO做什么

① 先确认当前状态（管理员 PowerShell）：

管理员 PowerShell
# True = Secure Boot 开着（必须去关），False = 已关（可跳过）
PS> Confirm-SecureBootUEFI

# 顺便确认是不是 UEFI 引导：报「不支持」就是 legacy/CSM
PS> $env:firmware_type

② 进固件设置关 Secure Boot：重启时按厂商键（Del / F2 / F10，视机器而定）， 在 Security 或 Boot 页找到 Secure Boot 设为 Disabled； 若没有独立开关，先把 CSM / Legacy Support 关掉，Secure Boot 选项才会出现。

③ 关快速启动：控制面板 → 电源选项 → 选择电源按钮的功能 → 更改当前不可用的设置 → 取消勾选「启用快速启动」，保存。

SEE看到什么
  • Confirm-SecureBootUEFI 返回 False。
  • $env:firmware_type 返回 UEFI（不是 Bios）。
  • 电源选项里「启用快速启动」的勾已经去掉。
IF NOT不对怎么办
  • Confirm-SecureBootUEFI 报「此 cmdlet 不支持此平台」：机器在 legacy/CSM 模式引导， 必须先在固件里切成 UEFI 引导（同时把系统盘从 MBR 转 GPT 才装得回去），否则工具跑不起来。
  • 固件里根本没有 Secure Boot 选项：老平台可能本来就没有，跳过即可；只要 Confirm-SecureBootUEFI 返回 False 就行。
  • 找不到「启用快速启动」：有些机器该项被隐藏，需要先「更改当前不可用的设置」；或该机未启用休眠，本身就没有快速启动。
关掉 Secure Boot 是有代价的，别长期放着

它保护整条开机链。为了跑一次解锁而长期关闭，等于长期放弃这层保护。 做完记得改回来——第 9 节会讲恢复的时机和顺序。

步 4仅 Turing（GTX 16 / RTX 20）：打开 GSP 并重启

这块只针对 Turing。RTX 30 / 40 系请直接跳到第 5 步——给 30 / 40 系开这个开关是错的， 已有 3080 20GB 魔改卡因此被打回厂值的实例。

原因很简单：Turing 的 Windows 驱动必须运行在 GSP 模式下，否则 legacy 初始化路径在被解锁的卡上会 TDR 循环或报 Code 43。

DO做什么
管理员 PowerShell · 01_release-v2.1.9 目录内
# 设 EnableGpuFirmware=1，只影响 Turing 显示设备
PS> cd .\01_release-v2.1.9
PS> .\enable-turing-unlock.ps1

# 然后必须真正重启（开始菜单 → 重启，不是关机再开）

重启后验证：

重启后 · 管理员 PowerShell
PS> nvidia-smi -q | Select-String -Pattern "GSP|Firmware"
SEE看到什么

GSP 固件版本一栏不是 N/A，而是一个具体版本号。同时 EnableGpuFirmware 的值为 1。这两条都成立，才算过。

IF NOT不对怎么办
  • 版本仍是 N/A：① 没有真正重启（休眠恢复不重新初始化驱动，改了等于没改）； ② 驱动版本过旧，不支持 GSP 模式，升级驱动后重试。
  • 脚本报拒绝访问：必须管理员 PowerShell，普通权限改不了显示类注册表键。
  • 想撤销：.\enable-turing-unlock.ps1 -Remove，然后重启。
  • Linux 机器：不要跑这个脚本（它是 Windows 注册表脚本）。Linux 走 GSP-RM 运行态检查， 专有驱动 545+ 默认启用，但可能被 NVreg_EnableGpuFirmware=0 关掉。

步 5制盘

这是唯一需要联网、也是唯一容易搬错文件的一步。制盘的本质是：把 NVIDIA 公开包里的固件 在本地下载、按 SHA-256 校验、抽取，再生成这块卡需要的 7 个载荷文件 + 1 个启动程序。 包里不分发固件，所以首次必须联网。

DO做什么

① 在目标机上制盘（推荐——脚本会自己识别本机是哪一代）：

Windows PowerShell · 01_release-v2.1.9 目录内
PS> cd .\01_release-v2.1.9
PS> .\make-usbroot.ps1

② 制盘机上没有目标卡时，必须显式指定家族，否则脚本会直接报错退出：

异机制盘 · 家族别名
# RTX 40 系（Ada）
PS> .\make-usbroot.ps1 -Family 40

# RTX 30 系（Ampere）
PS> .\make-usbroot.ps1 -Family 30

# RTX 20 / GTX 16（Turing）
PS> .\make-usbroot.ps1 -Family 20

# 三代打同一张盘，服务多种卡（也可以写 ad102 / ga102 / tu10x）
PS> .\make-usbroot.ps1 -Family all

# 制盘机没有 Turing 卡时，跳过制盘机的 GSP 检查（不豁免目标机前置）
PS> .\make-usbroot.ps1 -Family 20 -SkipGspCheck

③ 按脚本打印的清单搬文件：

  1. 把 usbroot\ 里的文件复制到 U 盘根目录（不要连文件夹一起拖，不要建子目录）。
  2. 把 BOOTX64.EFI 放进 U 盘的 EFI\BOOT\（该目录不存在就新建）。
SEE做什么之后会看到

脚本会一路打印 [extract] / [generate] / [ok]，最后是逐文件的清单， 每行「文件名 + 字节数」。以 RTX 40 系为例，正常是这样结尾的：

make-usbroot.ps1 输出末尾（RTX 40 系样张）
  booter_load_ad102.bin              (字节数)
  gsp_boot_desc_ad102.bin            (字节数)
  gsp_boot_ad102.bin                 (字节数)
  fwimage_ad102.bin                  (字节数)
  fwsignature_ad102.bin              (字节数)
  scrubber_ad10x.bin                 (字节数)
  v67-ad102-four-plm.bin             (字节数)
  BOOTX64.EFI                        (字节数)

DONE (ad102). Copy the CONTENTS of .\usbroot to a FAT32 USB stick root.
Unlock mode requires the v67-*.bin payload for the target card's family

数一下：7 个 .bin + 1 个 BOOTX64.EFI，共 8 行。家族标识会跟着变 （ad102 / ga102 / tu10x），-Family all 则三代各一套。

其中 v67-*-four-plm.bin 是解锁载荷。它不在 U 盘上，EFI 就会切进「回放模式」—— 不执行解锁，但仍会断开驱动、执行签名固件，所以回放不是只读检查。

IF NOT不对怎么办
  • 报 localhost: no supported NVIDIA adapter ... found on this machine： 制盘机不是目标机（或本机只有核显）。用 -Family 40|30|20|all 显式指定。
  • 报「无法加载文件，因为在此系统上禁止运行脚本」：执行策略拦的，用 powershell -ExecutionPolicy Bypass -File .\make-usbroot.ps1 单次绕过，不要改全局策略。
  • 下载失败或 SHA-256 不符：换传输源，不要换固件版本、不要关校验。 国内 raw.githubusercontent.com 被阻断是已知情况，Turing 归档会自动回退 jsDelivr / 代理， 同一对象、按钉定哈希把关。也可以直接把文件离线放进 inputs\，哈希匹配就会被接受。
  • Windows 下 Invoke-WebRequest 报 TLS 错误：改用 WSL 或 Git Bash 跑 make-usbroot.sh （bash make-usbroot.sh --family all）。
  • U 盘不是 FAT32：UEFI 一般只认 FAT。超过 32 GB 的盘 Windows 自带的格式化工具不给 FAT32 选项， 需要用第三方工具；或换一个小容量盘。
进阶：让脚本直接写进 U 盘

-Out 可以指到盘符，省掉一次手动复制：.\make-usbroot.ps1 -Family 40 -Out E:\。 注意 BOOTX64.EFI 仍会被放到 E:\ 根目录，你还是要手动把它移进 E:\EFI\BOOT\。 另外这种方式会跳过「照着清单核对」的习惯动作，第一次做建议还是走默认输出。

步 6从 U 盘启动并执行事务

DO做什么
  1. 从系统里选「重启」，启动过程中按一次性启动菜单键（F12 / F11 / F8 / Esc，视厂商而定），选 U 盘。 不要用「关机再开机」——那是休眠路径，GPU 状态不对。
  2. 看到版本屏后，按 空格或回车。
  3. 等它跑完，自动链回系统。
KEY按键语义（这是设计，不是 bug）

版本屏显示后，只有空格或回车会继续。其他任何键、或 30 秒不操作，都会中止事务并交回系统引导器。 中止时没有任何 GPU 写入，等于什么都没发生。

SEE看到什么
  • 事务执行期间，目标 GPU 可能黑屏或冻结在最后一帧——正常。loader 主动断开了 GOP 句柄， 让系统引导器自己重建显示。不要急着断电。
  • 跑完后自动进入系统（按 Windows Boot Manager → Linux 引导器 → 通用 EFI 的顺序查找）。
  • U 盘根目录出现 loader.log，每行带 [+ms] 前缀。

如果控制台刷新很慢（有些核显输出慢到 1 行/秒），在 U 盘根建一个空文件 tx-quiet.txt，控制台就只显示裁决行，loader.log 仍然全量记录。

IF NOT不对怎么办
  • 按了键没反应 / 30 秒自己退出了：这就是中止，重来一次按空格。
  • U 盘不在启动菜单里：Secure Boot 没关（第 3 步），或 U 盘不是 FAT32，或固件只列了 Windows Boot Manager（换个 USB 口、开 CSM 试试）。
  • 卡在 RECONNECT: ConnectController 或事务后卡死/复位：部分 AMI 平台已知问题。 在 U 盘根放一个空文件 no-reconnect.txt，跳过目标 GPU 的 GOP 重连，彻底断电后重来。
  • 日志里 booter status 0x89：桥的 Bus Master 没开。翻 loader.log 里的 DMA-PATH / BRIDGE-BME 两行，按手册 08 章处理。

步 7回到系统里验证

这一步最不能跳。EFI 屏幕全绿只证明事务路径跑完了， 真正的验收是「驱动加载之后，覆盖值还在不在」。

DO做什么
管理员 PowerShell · 01_release-v2.1.9 目录内
# 只读诊断，dump 每块 NVIDIA 显示设备
PS> cd .\01_release-v2.1.9
PS> .\ssdiag-x86_64-windows.exe

# 多卡机器按 DeviceID 缩小范围
PS> .\ssdiag-x86_64-windows.exe --select 2504

# 仅在「门还开着但 SS 被冲回」时用：重写 SS0/SS1 并读回（写操作）
PS> .\ssdiag-x86_64-windows.exe --reapply

然后按下面的判据读结果，先看家族，再看门，最后看 SS 值。

SEE看到什么 → 怎么判
读回结果判断与下一步
SS0 = 0x88888888
SS1 低四位 = 0x8		覆盖值有效。再做同负载性能对比（见下）
Ampere / Ada：门仍开，但 SS 值不符选择器被驱动冲回了。用 --reapply 写回，再读一次
Turing：门被重锁，但 SS 值正确正常交棒状态，不要判失败。Turing 的解锁路径本来就主动重锁 PLM
门关闭且 SS 无效，或卡已失电修复工具救不回来。按第 8 步重走一次 U 盘事务
Secure Boot 也会挡住诊断工具

ssdiag 内嵌的 pmxdrv.sys 是 Intel/COMODO 交叉签名的，没有 Microsoft 根， 在 Secure Boot 开启的机器上加载会被拒绝。所以「关 Secure Boot」不只是为 EFI，也是为诊断。 --dry-run 不加载驱动，可以先跑它。

性能对比怎么做才算数

  • 先有基线。解锁前用固定张量形状、精度、批次大小和功耗设置跑一次，落盘保存。
  • 同条件复测。解锁后跑完全相同的负载，只改「解锁状态」这一个变量。
  • 核验基准工具本身。确认输入张量非零、没被编译期常量折叠掉——社区有过实例， 上游 mmapeak 存在编译期零输入坍缩，后来改用运行时随机化的 fork 才测准。用 FP32 平价做控制标定噪声。
  • 分开汇报。「固件执行成功」「系统存活」「性能变化」是三件事，别合成一个「成功」。
IF NOT不对怎么办
  • SS 有效但性能没变：先确认是不是撞功耗墙——观察 Board Power、Hot Spot 与限频原因。 解锁放开的是发射率，不是功耗上限。
  • 驱动报 Code 43 / TDR：Turing 未开 GSP 时高发，回第 4 步；仍不行用 DDU 重装驱动。
  • Linux 上「日志全绿但没提升」：最常见的不是解锁失败，而是运行时空闲断电把易失状态清掉了。 检查 NVreg_DynamicPowerManagement 是不是 0x02，是的话改成 0x00 并重建 initramfs。

步 8失败怎么退回

目标不是「救活这次」，而是让机器回到干净可用的状态，然后决定要不要重来。

DO做什么
  1. 立刻彻底断电：长按电源 5–10 秒，或拔电源线/电池。不要在同一会话里反复重试—— 固件可能还在运行、DMA 缓冲仍被占用，风险会叠加。
  2. 拔掉 U 盘，正常开机进系统。
  3. 确认系统可用：能进桌面、设备管理器里显卡没有黄色感叹号。
  4. 保留证据：把 loader.log 复制到硬盘上（下次运行会覆盖它）。
  5. 再决定：按第 5、6 步重来一次；同一个失败点连续两次，就不要第三次了，去查手册 08 章。
SEE看到什么

系统正常进桌面、显卡工作正常、nvidia-smi 能正常输出。因为解锁是易失的， 断电重启之后本来就已经回到未解锁状态，不需要「还原」任何东西。

IF NOT不对怎么办
  • 进系统后花屏 / 驱动反复掉：先进安全模式，用 DDU 卸载驱动再装一次。
  • 连 BIOS 都进不去：清 CMOS（拔电源 + 取出纽扣电池 30 秒）。这只影响固件设置，不影响硬件。
  • 反复黑屏但能听到系统启动声：多半是 GOP 重连问题，下次制盘时保留 no-reconnect.txt。
别把「黑屏」当成硬件坏了

黑屏、事务失败、驱动异常本身不能证明硬件永久损坏，但也不能代替恢复后的设备检查。 判断依据是「断电重启后能否正常进系统 + 显卡能否正常出图」，不是黑屏本身。

收冷启动与长期使用

解锁是易失的：断电、冷启动、休眠恢复都会清掉。想一直保持，就得每次冷启动重放一次 U 盘事务。 这是设计取舍，不是缺陷。

场景解锁还在吗怎么办
重启（不拔电）不一定重新走一次 U 盘事务最稳
关机再开机没了重放
休眠恢复没了重放（休眠会掉电到 dGPU）
运行中 RTD3 空闲断电没了Linux 见第 7 步的 RTD3 配置

Secure Boot 什么时候改回去

  • 确认不再需要诊断和解锁后，进固件把 Secure Boot 改回 Enabled。
  • 下次要用时再关一次——反复开关比长期关闭安全。
  • 如果这台机器是长期测试机、需要频繁重放，考虑给 EFI 自签并让固件信任该证书， 这样不用关 Secure Boot 也能跑（上游支持这条路，但配置更麻烦）。
U 盘别急着格式化

下次冷启动还要用同一张盘。上游迭代较快，固件版本与载荷是配套的， 不要单独替换其中几个文件——要升级就整包换新、重跑一次 maker。

A六个「看着像失败，其实正常」

这些是最容易让人误判、进而做出错误动作的场景。看到它们，先对照，再决定要不要动。

你看到的实际性质该做什么
版本屏 30 秒后自己退出正常中止重来，按空格或回车。中止时没有写入
事务执行中 GPU 黑屏 / 冻结最后一帧设计行为等它链回系统，别断电
Turing 读回时「门被重锁」正常交棒只看 SS 值，别拿 Ampere 的判据套
SS 有效但性能几乎没变撞功耗墙看 Board Power / Hot Spot / 限频原因
Secure Boot 开着时诊断加载驱动失败预期内先关 Secure Boot，或只用 --dry-run
make-usbroot.ps1 报本机没有支持显卡制盘机不对加 -Family 40|30|20|all
还有一条不是「正常」，但容易误解

U 盘上缺了 v67-*-four-plm.bin 时，EFI 会进入回放模式：不执行解锁载荷。 但它仍然会断开驱动、执行签名固件、可能复位 GPU——回放不等于只读检查。 不要拿它当「安全试跑」。
